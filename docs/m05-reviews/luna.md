## Findings

### 1. [critical] Anonymous clients can lock out every owner reconnect
**Location**: `manager/src/manager/state/devices.rs:118-145`; also `manager/src/manager/state/workers.rs:255`
**Finding**: `remote_attempt` applies one durable 120-per-minute counter to every owner handshake, including successful authentication, and worker enrollment. The public listener accepts TLS clients with no certificate, routes `/owner/v1/connect` to the owner protocol, and discards the peer address (`manager/src/public_http.rs:76-87, 154-162`). Any unauthenticated Internet client can therefore submit 120 owner hellos in a minute; all later owner authentication/enrollment and worker enrollment then return `RateLimited` until the shared window resets. The test at `manager/src/manager/state/devices/tests.rs:184-203` confirms the global lockout behavior.
**Evidence**: `connect_owner` calls `remote_attempt()` before checking manager identity, role, credential, or device state. `enroll_worker` calls the same function. A caller needs no valid invitation or credential to consume the budget. This makes a trivial unauthenticated flood deny remote access to every paired device after a manager restart or network loss.
**Suggestion**: Rate-limit by a bounded source-address bucket and separate owner authentication, owner pairing, and worker enrollment budgets. Keep a global resource cap for CPU/connection pressure, but do not let anonymous traffic exhaust the authentication budget for all devices.

### 2. [warning] A slow inference verification blocks all other owner operations
**Location**: `manager/src/owner_http.rs:193-210`; `manager/src/manager/devices.rs:118-142`
**Finding**: The single snapshot semaphore is acquired before every owner operation and held through `owner_operation`. The `VerifyInference` branch keeps that permit while awaiting the provider request, which has a 10-second timeout (`manager/src/manager/provider.rs:132, 174`). During that wait, every other paired connection fails semaphore admission with `Busy`, including task cancellation, approvals, and input control.
**Evidence**: The design bounds snapshot materialization and serialization with a global permit. This path holds it across network I/O unrelated to materialization; `owner_http::transfer` uses `try_acquire_owned`, so other viewers are refused rather than queued while verification runs. A paired device can repeatedly cause this cross-device control outage without exhausting the eight-connection budget.
**Suggestion**: Release the materialization permit while performing provider verification, then reacquire only when needed to serialize the result. Keep snapshot and large-artifact materialization under the global bound; let ordinary bounded operations use independent admission.
