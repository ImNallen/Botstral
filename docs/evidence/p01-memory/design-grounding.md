# Run flow
SubmitRun has bot/session/configuration revision/prompt and no conversation ID. RunView has request/configuration/summary/turns. manager/src/manager/state/runs.rs transcript() starts only with prompt/images then same-run tool/assistant messages. It never reads stored documents or conversation history. validate_run_admission around line219 precedes persisted RunView/insert_run around704; both direct owner and routine admission use it. It takes &self while document reconciliation takes &mut self. Startup reconciles documents before run recovery. Each admitted turn already persists messages and encoded provider request before dispatch with token/cost holds, around runs.rs:502. A new run should get latest reconciled current memory; an admitted run should keep its snapshot across later edits and restart. Legacy runs must not spontaneously acquire new memory after upgrade. Existing run protocol has no System role. Avoid a new role or wire field unless it clearly earns its compatibility cost. A bounded source/revision-labeled User context can treat memory as data while deterministic manager permissions remain authoritative.
