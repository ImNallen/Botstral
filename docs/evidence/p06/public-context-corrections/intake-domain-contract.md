# Private inventory admission contract

Two rechecks rejected incomplete hand-picked context checks. The shared failure premise was that provider system/tool text and its request envelope represented every fixed value later scanned in ordinary conversation. The second reviewer proved that mandatory request keys, configuration state and assistant-message discriminators were omitted. Root separately proved that a configured model name and an issued TOTP code could poison the same global retained-value scanner. Extending the example list is insufficient.

The prospective context now uses the actual whole shared protocol schema, generated from Rust types, together with the same provider envelope, system messages and tool-definition builders used in production. A cached schema includes request fields, metadata fields, variants and discriminators as those types evolve. Current typed inference configurations and recovered/imported memory entries are included because new conversations consume them. Shared memory and screenshot prefaces are included from the constants used by the real transcript builder. Public item or review metadata is added at the relevant operation boundary.

One state-owned context builder supplies both owner-created epoch admission and generated current-code admission. A colliding owner-created value produces a final value-free rejected receipt before an epoch exists. Rejected rotation cannot change its original item. A colliding generated code refuses before encryption, retention, consumption or private response. This preserves the original global scanner and retired inventory instead of deleting known private values to make old operations succeed.

The regression matrix exercises full plain and Computer-enabled conversation admission and benign completion after rejection. A second behavior driver derives candidate tokens from actual request and message objects and an actual prepared provider body. Every accepted candidate must preserve a complete conversation, including after rotation and removal. This driver does not merely assert that the guard recognizes a dictionary copied from its implementation. Preexisting public-memory and configured-model collisions are covered. A deterministic seed produces a code that collides with a configured model; the before run releases and retains it, while the corrected run retains zero codes and leaves public configuration readable.

This prevents the demonstrated unavoidable conversation poison path. Arbitrary future user, website, tool and model text can still independently coincide with a private value and refuse publication. A possible-release profile ledger remains conservative after a refused or uncertain fill and may require a verified empty replacement. No automatic profile reset, private-history deletion, or repair without a pre-entry backup is added.

Provider message, tool-call and multimodal-part wire shapes now use typed serializers with generated schemas. Intake consults those same schemas, so adapter-specific keys such as tool_calls and image_url do not depend on a sample that happened to contain a particular message variant. The runtime JSON remains the same. Focused vision tests verify the actual multimodal provider request. The behavior driver now includes a real assistant tool call and multimodal source message and covers 116 observed tokens.
