# Selected security correction

Root read all three candidates and the cross-judge. Scores are A22/25, B19/25, C12/25, matching the independent judgment. A is the base. It derives recorded ownership from immutable tasks.worker and cross-checks TaskView identity, retains every recorded emission, and bounds preparation to one root plus one exact remembered successor. B contributes durable ownership discipline, implemented through the existing immutable column rather than a new worker-copy migration. C's extra release ledger, ignored completeness and arbitrary eight-destination budget are rejected.

Screen requires a known worker-owned profile and exact complete coverage of manager-recorded Released/Applied/Uncertain uses. It decrypts each recorded epoch for integrity, then screens password emissions against username/password only and TOTP emissions against the exact retained code only. Seeds and unrelated provider/connector/login/code inventory are not queried. Duplicate supplied IDs refuse. Old use authority is never required. Unknown, omitted, foreign, unemitted or corrupt history refuses.

Prepare returns exact cached roots/successors before capacity or secret comparison, including terminal states. A changed destination cannot allocate. The remembered successor keeps the root deadline, exact binding/destination and revision+1 cause with valid source; no other second row is allowed. Legacy multiplicity refuses rather than deleting history. Additional fills require new admitted parent tasks.

Mandatory graft from the judge: rejected first destination guesses also need durable admission before the global public-destination scan. Migration16 adds a table with at most one immutable first-attempt row per task, with its execution. Existing review history is checked first and needs no backfill. No rejected destination or digest is stored because an attempt with no review is permanently closed for that parent; there is no retry-status API or recovery decision requiring request comparison. A committed review supplies exact request comparison. This is smaller and reveals less than storing a digest. A crash after claim but before review can burn the parent safely; a new task is the recovery. At most one global destination comparison per owner-admitted parent remains, not a universal claim of zero membership signals.

Implementation may split existing Prepare and Screen into private uses/preparation.rs and uses/profile.rs submodules to keep the manager boundary readable. State remains the only writer and the wire API is unchanged. No emission ledger or deleted retained data is introduced. New schema/version fixtures and explicit old-test expectation changes require verification. All design agents were read-only and explicitly stopped.
