# PR56 worker screening and preparation correction

Two automated security findings at source `13580e424dd83a568a88714593d74924440bc840` were confirmed against production methods. [Profile screening](https://github.com/ImNallen/Botstral/pull/56#discussion_r4421589133) could compare arbitrary worker text with global unrelated secret inventory. [Repeated preparation](https://github.com/ImNallen/Botstral/pull/56#discussion_r4421589139) could allocate fresh records under one admitted task until the lifetime capacity was exhausted.

## Corrected contract

The manager derives profile ownership from retained use records and immutable task worker assignment, cross-checking task identity and approval binding. Screening requires a known owned profile and exact complete coverage of manager-recorded emissions. It compares only delivered username/password values for password fills and exact issued codes for TOTP fills. It decrypts the recorded encrypted epoch for integrity and retains protection after item removal or authority expiry. A prepared profile without emissions screens without consulting secret inventory. Unknown profiles, duplicate or omitted identifiers, foreign assignment, inconsistent parent identity and missing codes refuse. Ordinary public-channel screening remains broader.

Preparation returns an exact cached root or remembered successor before capacity checks and global secret comparison. Terminal retries preserve their identifiers and deadline. Destination changes refuse. The sole remembered successor requires the original revoked password root, revision increment, exact context and still-valid approval provenance; it cannot extend the root deadline. Additional fills require new admitted parent tasks. No retained release history is compacted or deleted.

The first destination comparison also needed a durable limit. Otherwise rejected guesses could still probe global inventory without consuming a use row. Schema 16 records one immutable preparation attempt per task before that comparison. Failed comparisons and crashes before review creation close the parent; recovery uses a new admitted task. Rejected destinations and digests are not stored. Successful review history provides retry comparison. The remaining bound is one global destination comparison per owner-admitted parent, not universal absence of membership signals.

[The selected design](selection.md) records the three-candidate comparison and independent judgment. [The source manifest](review-source.json) binds the correction files used for independent review.
