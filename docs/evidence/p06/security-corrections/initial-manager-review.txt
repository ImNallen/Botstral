Verified findings

1. P1. Device revocation does not revoke credential authority already granted by that device.

Relevant code is manager/src/manager/state/credentials/uses.rs:110 and :177, with manager/src/manager/state/devices.rs:235. The decision checks the owner lease once but retains no approving-device authority. Device revocation disconnects the owner without invalidating the credential use.

The two device probes approve with an enrolled owner device, revoke it through the actual manager API, and then test release or cancellation. The revoked device itself fails authorization, but the approved worker still receives a Released payload. Revocation after release leaves the use Released, the task Running, and zero durable cancellations.

Actual output in adversarial.log includes:
revoked_device_rejected=true; previously_approved_release_returned=true
 after_device_revoke use=Released; task=Running; durable_cancellations=0

Required output is no credential release after revocation. An affected released scope must become uncertain and receive durable cancellation. This violates the selected design's explicit device-revocation contract. Both probes fail their expected-safe assertions. They change only device revocation after otherwise valid approval.

2. P1. Ordinary URL encodings bypass private screening and metadata publication checks.

Relevant code is manager/src/manager/provider.rs:527, especially :534, and manager/src/manager/state/credentials/uses.rs:493. Only uppercase percent escapes with %20 for spaces are generated for comparison.

The first probe releases an owned fixture password, verifies that uppercase percent encoding is rejected, then changes only escape-letter case. The manager returns Screened with the encoded private value. The same encoded value passes update_login, persists as a label, and is returned by accessible_login_items. A separate probe uses reqwest::Url::query_pairs_mut to produce standard form encoding with plus signs for spaces. That encoded password also persists and becomes bot-visible.

Actual output in adversarial.log includes:
uppercase_percent_refused=true; lowercase_percent_screened=true; encoded_metadata_persisted=true; bot_visible=true
raw_refused=true; form_urlencoded_metadata_persisted=true; bot_visible=true

Required output is refusal before screening response or metadata persistence. These are ordinary URL encodings covered by the claimed screening contract, not arbitrary transformations or covert channels. No raw fixture value appears in the evidence output.

3. P1. Numeric private values survive run settlement and public run reads.

Relevant code is manager/src/manager/provider.rs:563, manager/src/manager/state/memory/entries.rs:143, and manager/src/manager/state/runs/settlement.rs:91. The shared scanner ignores JSON numbers. P06 applies this existing scanner limitation to newly supported numeric passwords and credential inventory.

The probe stores a generated six-digit password through write_login. It confirms that the same digits as a string are rejected. It then submits a recorded assistant tool response whose RequestWakeup.at number contains those exact digits. finish_run_call persists the response, and the actual public run API returns it. No inference request is sent.

Actual output in publication-adversarial.log is:
raw_string_secret_refused=true; numeric_secret_in_durable_run=true; numeric_secret_in_public_run=true

Required output is rejection before turn persistence and public return. The serialized run contains the literal private digits. This is not an encoding or a conjectured TOTP exploit. The probe verifies a stored numeric password; numeric TOTP publication was not separately exercised.

4. P2. Native receipt reconciliation can close a request against the wrong manager.

Relevant code is desktop/src-tauri/src/remote.rs:1113 and :1134, especially :1150. protected-status.json stores a request and status without manager identity. Pairing to another manager retains this file, and reconciliation uses the newly connected session.

The probe runs two real isolated managers with authenticated paired transport. Manager A commits a protected write. The probe restores Unresolved for that request to simulate a lost native receipt, signs out, and pairs the same desktop profile with manager B. Manager B has no login items. Reconcile returns ClosedWithoutCommit for A's committed request and persists that false closure.

Actual output in native-adversarial.log is:
stale_generation_refused=true; original_manager_committed=true; replacement_manager_has_no_items=true; replacement_manager_reported_closed_without_commit=true

Required output is to retain the unresolved request under manager A and refuse resolution by manager B. A closure from B cannot establish that A did not commit or fence a late write at A. This run proves false closure of an already committed write. It does not claim to reproduce a late network write after switching managers.

Reproduction and coverage

The three probe drivers are self-contained entry points with source in probes.rs, publication-probes.rs and native-probes.rs beside them. They temporarily include their probes in existing test modules, call unchanged production methods, and restore the original test files in finally blocks. No production implementation or existing assertion is modified. Run the drivers sequentially. Expected failure exits are intentional evidence, not passing tests.

The five independent passing manager probes verify a failed release transaction rolls back issued-code storage and consumption; a retry releases once; TOTP releases with five seconds remaining and refuses four; closed rotation cannot create a later epoch; and installation/kind mismatches refuse decryption. A separate matrix in the passing fence probe changes cancellation, worker identity, worker revocation, execution, task, origin, profile, form, field, submitter and item-origin policy independently. Each refuses. The native probe also confirms stale-generation writes refuse before creating an item.

The existing passing credential tests cover item/epoch authentication, create/rotate/remove retention, locked restart and restore, late create closure, revoked owner connections, one-shot release, document identity, remembered-rule precedence, fresh TOTP approval, permissions, generations, journal identity, input takeover, lock, rotation, expiry, missing profile history, missing issued codes and uncertain lost releases. The full manager suite adds publication and real backup/restore coverage. The actual paired native test scans owned desktop and manager files for raw and escaped fixture values and excludes private writes from the mutation journal.
