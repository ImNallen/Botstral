# First acceptance final harness review

The goal is a repeatable acceptance run whose verdicts prove the stated checks, preserve the campaign cap, and shut down owned resources. Two actionable defects remain in the reviewed harness. This review does not change the eight verified milestone checks or the open helper-routing check.

1. **High. Native cleanup can skip every remote cleanup operation.** `manager/tests/first_acceptance.py:910-913` catches `native.close()` failure, but calls `terminate()` and `wait(timeout=15)` without protection. A timeout escapes before the unit loop, provider scan, provider-key deletion, and report save. I reproduced this with the actual AST-extracted `cleanup` method and harmless local stubs. `close()` raised `RuntimeError`, `terminate()` succeeded, and `wait()` raised `subprocess.TimeoutExpired`. The only observed events were `native.close`, `native.terminate`, and `native.wait`. No remote operation ran. Isolate the fallback failure, record it, and continue independent cleanup. Preserve the failed native-cleanup verdict.

2. **Medium. Continuations accept an empty provider-secret scan.** Initial cleanup deletes `provider-key` at `manager/tests/first_acceptance.py:927`. `load_resume()` restores neither that file nor another comparison secret. `manager/tests/first_acceptance_remote.py:91-93` therefore returns `files=0`, `leaks=[]`, and `not_provisioned=True` for a resumed fixture whose vault is already provisioned. `manager/tests/first_acceptance.py:922` accepts that result. Continuation logs and state receive no byte scan. Report the scan as unavailable, or accept the original private key file for a bounded comparison during continuation cleanup. Do not treat absence of the temporary file as proof that the provider was never provisioned or that continuation evidence contains no key. This finding identifies missing coverage, not an observed credential leak.

The stock reconciliation helper sums all attempts in the fixture database and cannot safely attribute that sum to one continuation allocation. I found no proved cap bypass in this path. Unused continuation holds can reduce the allowance for later retries, but retaining them is conservative and is not a defect in this report. The cap and prior reservations must remain unchanged.
