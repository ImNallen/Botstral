# M03 independent design verdict

Select Astra as the base. Graft Sol's single transition reducer, removal of the old task-start path, bounded admission, and retryable document-write identity. No Luna graft closes a gap better than these candidates. Implement one manager authority and one worker journal, with relational state and transactional outboxes.

All three candidates were read end to end against the frame, grounding, acceptance contract and rubric. Scores assess the proposed design, not completed implementation evidence.

| Criterion | Astra | Sol | Luna |
| --- | ---: | ---: | ---: |
| Stable identity and atomic state, commands and events | 4 | 4 | 3 |
| Durable worker evidence and conservative reconciliation | 4 | 2 | 2 |
| Final authority and confirmed cancellation | 3 | 2 | 1 |
| Markdown source, rebuild and event replay | 3 | 3 | 2 |
| Existing ownership and maintainable interfaces | 4 | 4 | 2 |
| Actual-binary fault acceptance and preserved boundaries | 4 | 3 | 2 |
| Total | 22 | 18 | 12 |

Astra distinguishes semantic identity from fences, includes durable report receipts and journal incarnation, and models the approval-consumption crash gap conservatively. It specifies the strongest source-publication recovery and fault tests. Its remaining omissions are concrete and local.

Sol has the clearest reducer and explicit storage bounds. However, its rule permitting replay when the manager never received acceptance is unsafe after an acknowledgment loss and journal replacement. Its cancellation-completion exception can clear cancellation without stopped evidence. Returning snapshots for future cursors contradicts the acceptance contract. Its final authorization also becomes an ordinary execution command, leaving an insufficiently constrained delivery gap.

Luna exposes separate create/enqueue coordination, duplicates command and outbox concepts without defining their relationship, omits queued cancellation, and leaves process-group evidence unresolved. Its approval consumption occurs before command delivery. Its directory expansion adds unnecessary private-state complexity. It lacks journal replacement detection and a durable report acknowledgment protocol.

## Required synthesis before implementation

1. **Define the final authorization boundary precisely.** Use Astra's worker-initiated execution claim, after preparation and immediately before admission to the executor. Atomically verify the entire authoritative binding, current worker/session control, permission revision, expiry, revocation, unused execution identity and absence of cancellation. Persist consumption and its event together. The resulting permit belongs to this execution and current connection; it is not a reusable outbox command. Journal admission, then check local expiry, fence and cancellation again immediately before invoking the adapter. No later scheduling queue may separate these checks from invocation. Lost permits, reconnect and crashes never manufacture fresh authority. Revocation committed before the claim prevents admission; revocation committed after the claim cannot retroactively withdraw admission. State this distributed-system limit explicitly. Test delayed pre-claim invalidation and post-claim permit loss separately. Do not describe physical effect onset as atomic with the remote manager transaction.

2. **Bind journal incarnation before any execution delivery.** Persist the worker's journal incarnation in the manager before dispatching commands, and include it in report identity and recovery expectations. An acceptance acknowledgment may be lost after the worker has already acted. Therefore, manager nonreceipt is not proof of nonexecution. A changed or missing incarnation places every potentially delivered unresolved execution into attention, even if acceptance was never received. With the same intact incarnation, replay the original immutable command through journal deduplication. A corrupt journal must fail closed, never silently initialize an empty replacement. Test acceptance and effect followed by lost acknowledgment, journal replacement and reconnect. Retain semantic identity tombstones; storage pressure rejects new admission rather than deleting duplicate protection.

3. **Use one reducer with sticky cancellation and ordered evidence.** Apply Sol's reducer to every existing and new task-start route. Cancel queued, running, approval-blocked and attention tasks through one durable intent. Cancellation survives attention and all later acceptance, progress and completion reports. Results arriving during cancellation update preserved effect evidence but cannot clear cancellation; only durable stopped confirmation resolves it. A task already terminal before the cancellation transaction remains terminal. A late accepted report cannot regress approval or terminal state. Store per-execution report ordering and reject conflicting repeated report identities. Attention may return to execution only with evidence that continuation is safe and fresh authority; an owner acknowledgment alone cannot prove that an effect did not occur. Exhaustively check the transition table, including cancellation before acceptance and reordered reports.

4. **Bound recovery transport and report replay explicitly.** Use stable `(worker, journal incarnation, report sequence)` identities and manager acknowledgments only after transaction commit. Persist reports with outcomes and acceptance. Replay ordered pages bounded by both count and encoded bytes, with backpressure and a fixed high-water mark for each recovery pass. Acknowledge only durably ingested reports; acknowledge duplicates without applying transitions twice. Worker acknowledgment permits deleting report payloads, not semantic tombstones or required outcome evidence. Bound unresolved work and pending report storage by admission limits. Page journal inventories and reconcile all pages before admitting fresh execution. Test more reports than one page, acknowledgment loss, reconnect during pagination, duplicate pages and bounded queues.

5. **Finish Markdown publication recovery across files, index and events.** Retain Astra's flat private files, typed source kinds, revision checks, temporary-file sync, rename and directory sync. Graft Sol's retry identity using expected revision plus content identity. Persist document kind, revision and source references in the authoritative file. Rebuild derived index data before search after startup or a failed index update. Recognized abandoned temporary files must not make private-state startup fail. If document changes appear in authoritative events, reconcile published file revisions into idempotent publication events before serving replay or snapshots; a crash after rename cannot permanently lose that event. The index and event metadata must never restore missing source files or overwrite newer files. Test pre-rename, post-rename/pre-index, post-index/pre-response, malformed source and deletion of only the derived index. Generated-memory APIs cannot target owner instruction files or typed policy.

6. **Make event and snapshot bounds real.** Retain a durable head independent of pruned event rows. Append and prune in the state transaction. Return ordered retained pages whose cursor identifies their last included event. Reject future cursors. An expired cursor returns a snapshot and head from the same authoritative read, after source reconciliation. Use explicit aggregate admission limits so the complete snapshot fits a documented response bound; do not assume existing per-item limits bound total state. Tests must cross the retention boundary while mutations continue and then resume from the returned cursor without gaps.

## Implementation and acceptance order

Build failing actual-binary recovery acceptance first. Then implement protocol and additive migration, manager reducer and durable APIs, worker journal and claims, and source/replay recovery. End each unit with its behavior checks before proceeding. Preserve migration data, advance the future-version refusal sentinel to four, regenerate shared bindings, and replace the M02 restart expectation deliberately.

Use an independently durable synthetic effect ledger and a barrier between its commit and worker outcome persistence. Verify both reliable observation and unknown outcomes with unchanged effect counts. Run approval-field variations, atomic rollback, lost acknowledgments, manager and worker restarts, offline cancellation, source-publication crashes and multi-page replay through real binaries. Preserve production refusal, worker-only authorization, private permissions, current fences and release separation.

Synthetic `NoProcessGroup` stopped evidence verifies the durable cancellation protocol only. It does not prove production process-group termination. Keep that production evidence explicitly open for W01, or add a controlled subprocess-group fixture before making that claim. The final M03 record must name this boundary instead of treating a synthetic stop as full process-group acceptance.
