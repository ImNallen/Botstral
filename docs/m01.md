# M01 manager foundation

M01 retains one owner, named bots, and browser sessions across manager restarts. The browser can create bots and revoke sessions. Bot execution belongs to later milestones.

## Usage

```sh
make deps
make build
./bin/botstral --data-dir ./data --port 8080 --setup
```

The terminal prints a temporary local setup link. Setup creates the owner, closes its listener, and links to the main sign-in page. Subsequent starts use the same data directory and omit `--setup`.

## Shape

`internal/manager` owns SQLite, password verification, sessions, and HTTP policy. Its public interface contains configuration parsing and the manager lifecycle. The database stays private.

The singleton owner row has a primary key constrained to one. Bots and sessions reference that owner. A complete owner insert commits atomically. There is no separate setup-completed flag.

Main and setup use separate routers and sockets. Setup binds a literal loopback address with an ephemeral port. An expiring capability arrives in a URL fragment, enters page memory, and leaves browser history. Exact Host and Origin checks protect setup requests. The main router has no setup handler.

Session cookies contain random bearer tokens. SQLite stores their hashes and fixed seven-day expiry. Each protected operation validates its session inside its database transaction. Revocation deletes the row. A restart cannot restore it.

The React frontend lives in `web/`. Network responses enter through runtime schemas. Authentication, connection, and list loading have explicit states. Unauthorized responses clear private state. Disconnection preserves a visibly stale list and disables mutations. Aborted requests cannot restore data after sign-out.

## Design choice

Three independent design candidates and a separate judge selected one manager package. The following alternatives explain that choice.

| Structure | Decision |
| --- | --- |
| One manager package with independent setup and main routers. | Selected. It keeps transaction and authentication rules together behind a small interface. |
| Separate transport, authentication, and repository packages. | Rejected. Callers would coordinate transactions across interfaces with only one consumer. |
| A command loop owning every database operation. | Rejected. It adds queue, cancellation, and reply lifetimes where SQLite already orders writes. |

The judge contributed a fragment capability link and refusal to start an uninitialized manager without `--setup`. A separate setup-only command was rejected because simultaneous independent listeners let the owner continue directly to sign-in.

## Tradeoffs

M01 accepts loopback HTTP in exchange for keeping remote transport outside this milestone. It provides no proxy trust or device pairing. A complete frontend build precedes Go compilation so the release has one embedded asset source and no placeholder page. The binary then runs without Node or adjacent frontend files.

## Verification

`make verify` passed with Go race tests, vet, TypeScript checks, copied-binary acceptance, and both browser tests. The acceptance script creates a bot, restarts the manager, signs in again, and compares the original bot identifier. It also checks anonymous rejection, durable sessions, setup isolation and closure, revocation, and sign-out.

The parent independently drove setup, sign-in, creation, restart, sign-out, and revocation through the running browser app. The same bot identifier remained after restart and explicit sign-in. Anonymous and revoked requests returned `401` without bot data. The narrow layout had no horizontal overflow.

Native browser inspection found an unescaped hyphen in the setup username pattern. A browser validity test failed with expected `false` and received `true`. Escaping the hyphen made that test and the complete verification command pass.

Independent review reproduced a development startup race. Vite's first watch build could remove files while Go compiled or started. The watch command now preserves existing output. A normal release build still clears it. The parent observed disappearing assets before this fix and intact assets through four watch startups after it.

Local acceptance ran on Darwin arm64. A static Linux amd64 cross-build passed. Linux execution is left to the hosted verification job. Controlled-clock tests cover setup expiry rejection, and live tests cover listener closure after successful setup. The full 15-minute timer has not been waited out in a live test.

## Execution choices

Model the Domain put owner and session invariants in persisted structures. Exhaust the Design Space compared whole architectures. Laziness Protocol kept the small manager interface. Separate Before Serializing Shared State isolated the implementation checkout. Sequence Work into Verifiable Units produced storage, HTTP, and frontend commits in that order.

Build the Lever produced the repeatable acceptance script. Prove It Works required the running binary and browser. Test Behavior, Not Implementation made the username check exercise native validity. Fix Root Causes corrected the HTML pattern itself.

The throughput checkpoint resolved schema and listener contracts first. Independent design and review artifacts had separate outputs. One implementation owner held the coupled database, HTTP, and frontend work. Integration followed after that owner stopped.

The implementation preserved the accepted behavior contracts. The browser pattern correction changed no interface or ownership boundary. There are no unresolved product decisions for M01.
