# M01 manager API

The manager is an API-only Go service in `manager/`, using SQLite and salted Argon2id password hashes. It owns one installation owner, named bots, and independent seven-day sessions. Future desktop and mobile apps are separate clients with separate designs. M01 provides neither app.

## Startup and setup

`botstral` accepts `--data-dir`, `--port`, and `--setup`. The data directory defaults to `./data` relative to the process directory. The main port defaults to 8080. Port 0 selects an ephemeral port. The main listener always binds `tcp4` on `127.0.0.1`.

An unconfigured installation without `--setup` fails before listening. With `--setup`, it also opens a dedicated `tcp4` listener on `127.0.0.1:0`. One JSON record on standard error contains `bootstrapEndpoint`, `capability`, and UTC `expiresAt`. The endpoint ends in `/owner`. The capability contains 32 random bytes encoded as canonical unpadded base64url. Only its digest remains in the activation state.

The setup listener supports only `POST /owner`. It requires `Authorization: Bearer <capability>` and `Content-Type: application/json`. Its body is `{username,password}`. Success returns `201 {owner:{username}}`, creates no session, flushes the response, and closes setup. Invalid capability returns 403. Expired or cancelled activation returns 410 while reachable. An existing owner returns 409. Invalid input does not consume activation. Activation expires after fifteen minutes, closes on cancellation, and never survives restart.

Main has no setup route. Configured startup serves main normally and never reopens setup, including with `--setup`.

## Authentication and request policy

Sign-in takes no Authorization header. Every successful sign-in returns a new session secret once, alongside owner and session metadata. It does not rotate another session. Only SHA-256 token digests persist. Passwords use salted Argon2id with two concurrent KDF slots and throttled attempts.

Protected calls require exactly one Authorization value. The Bearer scheme is case-insensitive. The secret must be the canonical unpadded base64url encoding of exactly 32 bytes. Cookies and query parameters cannot authenticate. Missing, malformed, expired, and revoked credentials return 401. Session metadata and ordinary logs never contain session secrets.

Both listeners require their exact bound numeric loopback Host, including port. Every present Origin header returns 403, including an empty value or `null`. Native callers omit Origin. Forwarded headers do not affect policy. The manager supplies no CORS permissions. Responses use `Cache-Control: no-store`.

Unknown, escaped, and noncanonical routes return JSON 404 errors. Routes never serve HTML, assets, or redirects. No browser request marker, cookie, or CSRF contract exists.

## Main routes

All routes below have the `/api/v1` prefix. `S` is `{id,createdAt,expiresAt}`. `B` is `{id,name,createdAt}`. Identifiers contain 32 lowercase hexadecimal characters. Timestamps use UTC RFC3339. Lists order by creation time, then identifier, and use empty arrays when empty.

| Method | Path | Authentication | Request body | Success |
| --- | --- | --- | --- | --- |
| GET | `/health` | None | None | `200 {status:"ok"}` |
| POST | `/sign-in` | No Authorization header | `{username,password}` | `200 {token,owner:{username},session:S}` |
| GET | `/session` | Bearer session | None | `200 {owner:{username},session:S}` |
| POST | `/sign-out` | Bearer session | None | Empty 204 |
| GET | `/sessions` | Bearer session | None | `200 {sessions:[S]}` for active sessions |
| DELETE | `/sessions/{id}` | Bearer session | None | Empty 204, including an absent target |
| GET | `/bots` | Bearer session | None | `200 {bots:[B]}` |
| POST | `/bots` | Bearer session | `{name}` | `201 B` |

Self-revocation is allowed. Sign-out revokes the current session. Authorization and each operation share an immediate database transaction. Expiry is checked after transaction admission, so queued work cannot use an expired or previously revoked session.

## Input and errors

JSON bodies must contain one UTF-8 object with no unknown fields and at most 8 KiB. Usernames are trimmed and lowercased, with 3 to 64 ASCII letters, digits, dots, underscores, or hyphens. Passwords are preserved verbatim and contain 12 to 128 characters, at most 1024 bytes. Bot names are trimmed and contain 1 to 80 characters, at most 320 bytes, without control characters.

Errors use `{error:{code,message}}`. Malformed input returns 400. Authorization on sign-in returns `400 invalid_request`. Invalid credentials or sessions return 401. Request policy failures return 403. Missing routes return 404. Wrong methods return 405 with `Allow`. Oversized bodies return 413. Wrong media types return 415. Throttling returns 429 with `Retry-After`. Storage failures return 503 without storage details. Protected bot requests authenticate before application input parsing.

## Persistence and scope

The data directory has mode 0700 and the database has mode 0600. SQLite uses WAL, FULL synchronization, foreign keys, one connection, immediate transactions, and ordered checksummed migrations. The singleton owner and owner foreign keys are SQL constraints. Migration bytes and checksums remain unchanged by the move into `manager/`.

The API is local-only. Remote transport, TLS, pairing, refresh tokens, workers, model execution, and native credential storage belong to later milestones.

## Verification

`make deps` downloads the existing Go dependencies. `make verify` runs race tests, vet, builds `bin/botstral`, then runs `manager/cmd/acceptance`. The driver copies the binary outside the checkout and uses an absolute temporary data directory. It creates the owner, signs in as A, creates a bot, signs in as B, revokes B, stops and waits, then restarts. It verifies that A survives, B cannot read or mutate, and a fresh session C retrieves the same bot ID. It also checks anonymous rejection, sign-out, JSON route isolation, setup closure, and configured restart with `--setup`.

Go tests use real SQLite and controlled clocks for session and setup expiry, singleton races, transaction rollback, revocation ordering, request boundaries, and cancellation. Actual listener tests exercise success and cancellation closure. The tests do not wait fifteen real minutes for the setup timer.

`CGO_ENABLED=0 GOOS=linux GOARCH=amd64 go -C manager build -o ../bin/botstral-linux-amd64 ./cmd/botstral` checks static Linux compilation. Compilation alone does not verify execution on Linux. M01 checkboxes remain open for the parent's final verification and independent backend authentication review.
